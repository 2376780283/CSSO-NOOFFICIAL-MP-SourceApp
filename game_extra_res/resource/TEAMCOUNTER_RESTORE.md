# CSSO 2.0 TeamCounter 还原

本批重建数字计数、普通双方头像、大头像模式；保留 Android 的 cl_hud_scale 和自定义 CRC 头像。实现文件 game/client/cstrike/cs_hud_teamcounter.cpp。

## 使用与部署

同步 build/game/client/libcsso_client.so，以及本批 game_extra_res 内资源后完整重启。

- cl_hud_playercount_showcount 0：普通模式显示双方头像（默认）。
- cl_hud_playercount_showcount 1：普通模式显示双方人数。
- cl_hud_playercount_pos 0/1：顶部/底部。旧 hud_playercount_pos 保留并同步。
- cl_hud_scale：沿用现有整体缩放；顶部/底部分别使用相应屏幕锚点。

resource/hud/teamcounter_csso2.res 从 CSSO2 原包提取，坐标采用1080高参考。主面板横跨屏宽、高128，底部对子元素分别重排；大头像分数位于头像下方，底部模式位于头像上方。
clientscheme.res 增加四种原版字体定义，字体高度转换为本引擎480比例基准。字体文件沿用已归档的共用字体。
归档双方人数背景VMT/VTF、埋弹/拆弹、支配/宿敌和死亡SVG。旧 resource/hud/teamcounter.res 已不被该实现加载，暂保留兼容其他资源引用。

## 模式与状态

读取 gamemodes.txt 当前类型/模式的 uiattributes/teamcounter_largeavatars、teamcounter_noroundtimer。兼容原包直接类型/模式结构和旧包 gamemodes 层级。旧包没有属性时，军备竞赛使用大头像并隐藏计时器，死亡竞赛使用大头像但保留计时器。
头像按玩家索引缓存，身份变化/CRC变化时更新；缺失头像每两秒重试，沿用队伍默认头像。队伍边框、死亡骷髅、支配/宿敌标记、己方血条和大头像分数已接入。死亡时仅显示骷髅。

## UI 异常修正与汇编依据

- 0x1802cf75c、0x1802cf863 使用 avatar_ymax 做除法取余：普通头像先纵向填满两行，再向双方外侧增加列。上一版错误地先横排六列；现已纠正，底部仍逐头像翻转。
- 主面板启用 proportional 并显式使用 ClientScheme。上一版没有显式开启 proportional，使480基准的字体有按固定像素显示的风险。
- ApplySettings 强制 skip_autoresize，构造时也初始化该设置。EditablePanel::OnSizeChanged 的旧 pin 布局会在异步尺寸消息中覆盖显式子控件坐标；此HUD全部采用显式布局。
- 资源里的 TeamCT/TeamT/White 按 ClientScheme 颜色解析，避免把原版配色替换为玩家资源中的其他队伍颜色。
- 新布局文件缺失时保留计时器和比分的默认几何尺寸；完整图标、字体、背景仍需同步资源。
- 支配54/宿敌42的独立宽度、大头像分数配置高度已接入；换队会刷新默认头像，切换头像模式会重新栅格化状态图标。

## 样式二次修正

用户实机确认位置正确后，继续核对 0x1802cfc00 头像绘制和 0x1802d03e0 文本背景绘制：

- 0x1802cfd1d 跳转 0x1802d015e 的死亡分支仅绘制居中 elimination 图标，不绘制头像与边框。移除先前自行添加的暗化头像和死亡边框。
- 0x1802cfec9–0x1802cfeed 的血条位于头像边框内侧；去掉自行添加的黑色血条底板，避免盖住底边。0x180636d38 常量为0.2，低血量阈值改为20%。
- 状态图标按各自 wide/tall 栅格化并居中，使用配置颜色；普通与大头像切换会重建对应尺寸。
- 四种原版字体直接按1080参考高度28/46/14/24生成最终像素字号，避免先转为480整数基准再放大的精度损失。保留 Stratum2 Bold、weight0、抗锯齿和人数/标签阴影；自定义字体名仍走Scheme。
- 计时器、比分和大头像分数背景明确使用纯矩形填充并清除Scheme边框，文本inset归零。原版 0x1802cf3ab 在分数不大于0时跳过分数区，现同步处理。
- 样式修正版构建通过，日志 /data/data/com.termux/files/usr/tmp/csso2-teamcounter-style-fix-build.log，11.582秒。尚无该版本的实机渲染确认。

## 边框与血条颜色视觉对齐

确认 Panel::PaintTraverse 仅在存在 IBorder 时调用 PaintBorder。头像容器没有 IBorder，导致此前自绘边框和血条没有可靠的执行入口。改为独立子控件的 Paint：头像 z0、边框/血条 z1、状态图标 z2，避免依赖 Scheme 边框，并保留状态图标的上层绘制。

与原版 hudlayout.res 逐项核对一致：

- CT 边框 TeamCT：181 212 238 255；T 边框 TeamT：234 209 138 255。
- 正常血条：202 202 202 255；血量比例不高于0.2时：234 81 81 255。
- 普通/大头像边框为1080基准2/3，血条高度3/4；血条位于内侧底部，长度按精确浮点血量比例截断，取消先取整百分比造成的阈值与长度误差。
- 顶底布局不变。构建日志 /data/data/com.termux/files/usr/tmp/csso2-teamcounter-frame-color-build.log，13.743秒编译链接通过；配置对照和diff检查通过，视觉仍待实机确认。

## 配色来源固定

用户继续反馈边框和血条颜色与原版不同。资源数值相同不代表已经证明实机视觉相同：此前结论只能覆盖静态配置。现将头像边框资源中的 TeamCT/TeamT 改为原包 Scheme 对应的明确 RGBA，并给内置布局补全边框、正常血条、低血量血条四项配色，修复资源缺失时白色边框的回退。外部自定义颜色仍允许覆盖默认值。

这一步消除 Scheme 和缺失布局的配色来源差异，不证明已经定位用户当前实机差异。血条两种资源数值本次未改变；如果同步代码及布局后仍不同，需要实际截图区分颜色、血条可见性、亮度或合成差异。

## 行为审查后的修正

- 通过原版 RecvTable 字符串确认：0x180275ca0 读取 m_iGunGameProgressionWeaponIndex，0x180275e70 读取 m_iScore。军备竞赛的大头像分数及主要排序改用武器进度，其他模式沿用玩家分数；只显示正值分数。
- 大头像同分依次比较玩家分数、击杀降序、死亡升序和玩家索引。原版在武器进度后还比较比赛领先者/同队领先者，在死亡前比较助攻；本移植玩家资源未同步这些字段，因此这些分支仍未还原，不添加猜测规则。
- 0x1802d01e0 先绘制时间背景再决定文字/C4内容。时间背景拆为独立 Panel，安包、暂停或隐藏文字时保留背景；teamcounter_noroundtimer 隐藏整个时间区域。热身的文字显隐规则仍待确认。
- 0x1802cf2b6–0x1802cf2d0：保留时间区域的大头像从时间区域下沿开始，无时间区域时从顶部开始；不再把时间文字移到头像下方。底部保持镜像排列。
- 普通/大头像独立读取 wide/tall；大头像分数读取 xpos/ypos/wide/tall。默认普通头像位置和边框/血条 RGBA 不变。
- 本轮只修正有证据的行为差异；血条资格、实机颜色和 C4 精确节奏尚未确认。

## 安包图标缺失与闪烁修正

旧实现只检查 g_PlantedC4s 首个实体，但 C_PlantedC4::SetDormant(true) 会把实体移出列表，导致安包期间 HUD 丢失 bomb 图标。现在监听 bomb_planted/bomb_defused/bomb_exploded 和 round_start/round_prestart，并结合网络回合 m_bBombPlanted 及有效实体判断状态。实体休眠后保持图标，拆除切换绿色图标，爆炸隐藏，新回合清理。

再次对照原版 0x1802d0389–0x1802d03c1 及 PE 常量 0x1805f3a28（0.05f）：实体可用时严格按 m_flNextGlow - curtime < 0.05f 选择高亮色，否则普通色；移除上一版自行添加的100ms高亮窗口。拆除状态优先使用绿色图标。无实体时的事件兜底仍按 max(0.15, 0.1 + 0.9 * 剩余时间/总时间) 推进下一次闪烁时间，并采用同一个50ms判断。事件提供 mp_c4timer 回退；晚加入且实体始终不可用时无法取得准确剩余时间，闪烁加速时机可能偏差。

原版 0x1802d0230/0x1802d035c 直接检查实体列表数量并取首个实体，0x18027de50 的休眠处理也确实移除列表项。因此事件/网络状态兜底是本移植的额外兼容补偿，并非 CSSO 2.0 原版行为；上一轮把缺失路径推断当作用户实机根因的依据不充分。实体可用时的闪烁条件、配色和拆除优先级已按汇编核对，但不能把整个实现称为完全一致。

图标显式关闭背景/边框/输入并放到时间背景上层。原SVG资源仍需部署；编译通过不能代替实机显示验证，也不能证明当前用户遇到的缺失仅由实体休眠造成。
